Why These Technology Choices?

✦ Vite over CRA

Vite uses native ES modules and esbuild for near-instant dev server startup (<300ms vs CRA's 30s+). HMR is also much faster.

✦ TypeScript Strict Mode

"strict": true in tsconfig catches null checks, implicit any, and property access errors at compile time — not runtime.

✦ No UI Library

Zero dependency on MUI/Antd/Tailwind. Every component is hand-crafted. This demonstrates deep CSS understanding and is a unique portfolio differentiator.

✦ Vercel for Hosting

Free tier, automatic HTTPS, global CDN, preview deployments on every push. Each git push to main auto-triggers a production deploy.

1. Custom SVG Line Chart — How It Works

// LineChart.tsx — converting data points to SVG path coordinates
const W = 600, H = 160, PAD = 20;
const max = Math.max(...data.map(d => d.value));

// Map each data value to an (x, y) pixel coordinate
const pts = data.map((d, i) => ({
  x: PAD + (i / (data.length - 1)) * (W - PAD * 2),
  y: H - PAD - (d.value / max) * (H - PAD * 2),
}));

// Build the SVG path string: "M x0,y0 L x1,y1 L x2,y2 ..."
const path = pts.map((p, i) => `${i === 0 ? 'M' : 'L'} ${p.x},${p.y}`).join(' ');

// Area fill: same path + closing back along the bottom
const area = `${path} L ${pts.at(-1)!.x},${H} L ${pts[0].x},${H} Z`;

The key insight is linear interpolation: map a data value in range [0, max] to a pixel in range [0, H]. No external library needed.

4. CSV Export — Browser-native, No Library

function exportCSV() {
  const headers = ['Customer', 'Email', 'Amount', 'Status', 'Method', 'Date'];
  const rows = filteredTransactions.map(t =>
    [t.user, t.email, `$${t.amount}`, t.status, t.method, t.date]
  );

  // Convert array of arrays to CSV string
  const csv = [headers, ...rows]
    .map(row => row.map(v => `"${v}"`).join(','))
    .join('\n');

  // Create a temporary blob URL and click it — triggers browser download
  const blob = new Blob([csv], { type: 'text/csv' });
  const url = URL.createObjectURL(blob);
  const a = document.createElement('a');
  a.href = url;
  a.download = 'transactions.csv';
  a.click();
  URL.revokeObjectURL(url); // clean up memory
}

URL.createObjectURL creates a temporary in-memory URL. After the download, revokeObjectURL frees the memory. This is the browser-native way to download files without a server round-trip.

1. Custom useLocalStorage Hook — Generic TypeScript

// hooks/useLocalStorage.ts
// Generic <T> means this works for ANY data type — not just one
export function useLocalStorage<T>(
  key: string,
  initial: T
): [T, (v: T | ((prev: T) => T)) => void] {

  const [state, setState] = useState<T>(() => {
    try {
      const stored = localStorage.getItem(key);
      return stored ? (JSON.parse(stored) as T) : initial;
      // Lazy initializer: reads from localStorage ONCE on mount (not every render)
    } catch {
      return initial; // handles corrupted JSON gracefully
    }
  });

  useEffect(() => {
    localStorage.setItem(key, JSON.stringify(state));
    // Syncs to localStorage every time state changes
  }, [key, state]);

  return [state, setState]; // same API as useState — drop-in replacement
}

The useState lazy initializer (() => { ... }) is critical — it only runs once on mount. If you passed the localStorage.getItem() call directly (without the function wrapper), it would run on every render.

2. HTML5 Drag and Drop — No Library

// TaskCard.tsx — make the card draggable
<div
  draggable            // enables the DnD API on this element
  onDragStart={() => onDragStart(task.id)}   // record which task is dragging
>

// KanbanColumn.tsx — make the column a drop target
<div
  onDragOver={e => e.preventDefault()}   // REQUIRED: allows drop to fire
  onDrop={() => onDrop(columnId)}        // fires when card is released here
>

// App.tsx — the state logic
const [dragging, setDragging] = useState<string | null>(null);

function handleDrop(targetColumnId: ColumnId) {
  if (!dragging) return;
  setColumns(cols => cols.map(col => ({
    ...col,
    tasks: col.id === targetColumnId
      ? [...col.tasks, findTask(dragging)]    // add to target column
      : col.tasks.filter(t => t.id !== dragging) // remove from source
  })));
  setDragging(null);
}
⚠️ Common Mistake — Why e.preventDefault() is Mandatory

By default, browsers don't allow drops on most elements. onDragOver={e => e.preventDefault()} tells the browser "yes, this element accepts drops". Without it, the onDrop handler never fires.

const [modal, setModal] = useState<{
  open: boolean;
  mode: 'add' | 'edit';
  task?: Task;         // populated only in edit mode
  columnId?: ColumnId; // populated only in add mode
}>({ open: false, mode: 'add' });

// Add: open modal with empty form, targeted at a column
function openAdd(columnId: ColumnId) {
  setModal({ open: true, mode: 'add', columnId });
}

// Edit: open modal pre-filled with existing task data
function openEdit(task: Task) {
  setModal({ open: true, mode: 'edit', task });
}

// Save: handles both add and edit in one function
function handleSave(data: Omit<Task, 'id' | 'createdAt'>) {
  if (modal.mode === 'add') {
    // add with generated id and timestamp
    addTask({ ...data, id: crypto.randomUUID(), createdAt: Date.now() });
  } else {
    // update existing task in place
    updateTask(modal.task!.id, data);
  }
  setModal({ open: false, mode: 'add' });
}
💡 Best Practices Applied in TaskFlow

1) Generic custom hook — useLocalStorage<T> is reusable for any data type. 2) Lazy useState initializer — reads localStorage once, not on every render. 3) Immutable state updates — always spread/map, never mutate arrays directly. 4) Union types for constraints — Priority and ColumnId are string literal unions, not raw strings. 5) crypto.randomUUID() — browser-native UUID generation, no uuid package needed.

🔍 DevFinder — GitHub Profile Explorer

🔍
DevFinder — GitHub Profile Explorer

React 18TypeScriptGitHub REST API useCallbackPromise.allError Handling

Search any GitHub username to see their profile, repos, stars, and tech stack. No API key required — uses the public GitHub REST API. Handles 404, rate limiting (403), loading states, and language filtering.

1. Custom useGitHub Hook — All API Logic Encapsulated

// hooks/useGitHub.ts
export function useGitHub() {
  const [state, setState] = useState<{
    user: GithubUser | null;
    repos: GithubRepo[];
    loading: boolean;
    error: string | null;
  }>({ user: null, repos: [], loading: false, error: null });

  const search = useCallback(async (username: string) => {
    if (!username.trim()) return;
    setState({ user: null, repos: [], loading: true, error: null });

    try {
      // Promise.all fires BOTH requests simultaneously — not sequentially
      // Sequential (bad): 200ms + 200ms = 400ms total
      // Parallel (good):  max(200ms, 200ms) = 200ms total
      const [userRes, reposRes] = await Promise.all([
        fetch(`https://api.github.com/users/${encodeURIComponent(username)}`),
        fetch(`https://api.github.com/users/${encodeURIComponent(username)}/repos?per_page=30&sort=updated`),
      ]);

      // Granular error handling — different message for each error type
      if (userRes.status === 404) {
        setState({ ..., error: `No user found with username "${username}"` });
        return;
      }
      if (userRes.status === 403) {
        setState({ ..., error: 'GitHub API rate limit exceeded. Try again in a minute.' });
        return;
      }
    } catch (err) {
      setState({ ..., error: 'Network error. Check your connection.' });
    }
  }, []); // empty deps — function identity is stable, doesn't re-create on render

  return { ...state, search };
}

2. Why encodeURIComponent?

// SECURITY: always encode user input before using in URLs
fetch(`https://api.github.com/users/${encodeURIComponent(username)}`)

// Without encoding — URL injection attack:
// username = "john/../../admin" → URL becomes malformed/exploited
// username = "john doe" → URL breaks (space is invalid in URLs)

// With encoding:
// "john doe" → "john%20doe" ✓
// "john/test" → "john%2Ftest" ✓ (/ is encoded)

3. Language Filter — Derived State Pattern

// App.tsx — language filter is DERIVED, not stored in extra state
const [langFilter, setLangFilter] = useState('All');

// Extract unique languages from repos (Set removes duplicates)
const languages = [
  'All',
  ...Array.from(
    new Set(
      repos.map(r => r.language).filter(Boolean) as string[]
      // .filter(Boolean) removes null/undefined language values
    )
  )
];

// Filtering is computed inline — no useEffect needed to sync separate state
const filtered = langFilter === 'All'
  ? repos
  : repos.filter(r => r.language === langFilter);

This is the React golden rule: don't sync state — derive it. The filtered repos list is always computed from repos + langFilter. Adding a separate filteredRepos state would create a sync problem.

💡 Best Practices Applied in DevFinder

1) Promise.all — parallel API calls cut load time in half vs sequential awaits. 2) useCallback — search function has stable identity, safe to pass as prop or put in useEffect deps. 3) encodeURIComponent — always encode user input in URLs (security). 4) Granular error handling — 404 vs 403 vs network error all show different messages. 5) Derived state — language filter computed inline, not synced via useEffect.

🎯 Interview Questions — React & Hooks

Q1. What is the difference between useMemo and useCallback? Where did you use them? Hooks

useMemo memoizes a computed value. useCallback memoizes a function reference.

  • In NovaDash: useMemo for filtered transactions — expensive filter recalculates only when search changes, not on every render.
  • In DevFinder: useCallback for the search function — keeps the function identity stable so it can safely be placed in useEffect dependency arrays without causing infinite loops.
  • Key rule: useMemo(() => value, deps) vs useCallback(() => fn, deps). Both cache between renders until deps change.
Q2. Explain the useEffect in your useLocalStorage hook. Why is the dependency array important? Hooks
useEffect(() => {
  localStorage.setItem(key, JSON.stringify(state));
}, [key, state]); // runs ONLY when key or state changes

Without the dependency array [key, state], the effect runs after every single render — writing to localStorage even when the state didn't change. With the dependency array, it only writes when state actually changes, which is the correct behaviour.

Q3. What is the lazy initializer pattern in useState and why did you use it in TaskFlow? Hooks
// ✗ Bad — getItem() runs on EVERY render
const [state, setState] = useState(JSON.parse(localStorage.getItem('key') || '[]'));

// ✓ Good — function runs ONLY once on mount
const [state, setState] = useState(() => {
  return JSON.parse(localStorage.getItem('key') || '[]');
});

The lazy initializer (passing a function instead of a value) means React only calls it on the initial mount. Since localStorage.getItem is a synchronous DOM operation, calling it on every render would be wasteful.

Q4. How does your drag-and-drop work without a library? What event order is involved? DnD

HTML5 DnD fires events in this order:

  • dragstart → fires on the dragged element → I store the task ID in state
  • dragover → fires on potential drop targets (columns) → must call e.preventDefault() to allow drop
  • drop → fires on the column where card is released → I move the task between columns
  • dragend → fires on the original element → cleanup

The state update in handleDrop uses immutable array operations — filter to remove from source, spread to add to target — which triggers React to re-render both columns.

Q5. Why did you derive the language filter list instead of storing it in state? State Design

React's core principle: don't duplicate state. The language list can always be computed from repos, so storing it separately creates two sources of truth that can go out of sync.

// ✗ Bad — two synced states that can diverge
const [repos, setRepos] = useState([]);
const [languages, setLanguages] = useState([]); // must be kept in sync manually

// ✓ Good — one source of truth, language list is derived
const [repos, setRepos] = useState([]);
const languages = ['All', ...new Set(repos.map(r => r.language).filter(Boolean))];
// Automatically up to date whenever repos changes

🎯 Interview Questions — TypeScript

Q6. How did you use TypeScript generics in your custom hook? Generics
function useLocalStorage<T>(key: string, initial: T): [T, Dispatch<T>]

The <T> generic parameter means the hook works for any type — useLocalStorage<Column[]> for Kanban columns, useLocalStorage<string> for a theme preference, etc. TypeScript infers T from the initial value, so callers get full type safety without writing the type explicitly.

Q7. What is a string literal union type and why is it better than a plain string? Types
// Plain string — no safety
type Priority = string; // 'urgent', 'asap', 'whenever' — all valid, bugs lurk

// String literal union — compile-time safety
type Priority = 'high' | 'medium' | 'low';
// task.priority = 'urgent' → ❌ TypeScript error at compile time

With a union type, TypeScript exhausts all possibilities. In a switch statement, if you add a new priority value later but forget to handle it in the UI, TypeScript's never type can catch it.

Q8. What does Omit<Task, 'id' | 'createdAt'> mean and why did you use it? Utility Types
function handleSave(data: Omit<Task, 'id' | 'createdAt'>) { ... }

Omit<T, K> creates a new type by removing keys from an existing type. Here, the modal form collects all Task fields except id and createdAt — those are generated server-side (or by crypto.randomUUID() and Date.now()). Using Omit avoids duplicating the Task interface and keeps it DRY.

🎯 Interview Questions — Performance

Q9. How did you build charts without a library? Is that a performance concern? Performance

Each chart is a React component that renders an <svg> element. The data points are mapped to (x, y) pixel coordinates using linear interpolation. SVG is rendered by the browser's GPU-accelerated compositor — it's actually very performant for static/semi-static charts.

Performance comparison: Chart.js bundle = ~200KB. My custom SVG charts = 0KB extra. For a portfolio dashboard with mock data, the custom approach is strictly better. For real-time streaming data with 10,000+ points, a library would be justified.

Q10. Why is the portfolio website faster than a typical React app? Performance
  • No JavaScript framework — zero React/Vite bundle (~170KB saved). Pure HTML loads in <100ms.
  • No npm dependencies — no package.json, no node_modules, no bundler.
  • CSS animations over JS animations — CSS transforms run on the GPU compositor thread, never block the main thread.
  • IntersectionObserver — scroll detection with zero scroll event listeners (which can cause jank at 60fps).
  • Lighthouse score typically 95–100 for plain HTML sites like this.

🎯 Interview Questions — APIs & Async State

Q11. Why did you use Promise.all instead of two separate awaits in DevFinder? Async
// ✗ Sequential — 200ms + 200ms = 400ms
const user = await fetch('/users/john').then(r => r.json());
const repos = await fetch('/users/john/repos').then(r => r.json());

// ✓ Parallel — max(200ms, 200ms) = 200ms (2x faster)
const [userRes, reposRes] = await Promise.all([
  fetch('/users/john'),
  fetch('/users/john/repos'),
]);

Both requests are independent — the repos endpoint doesn't need the user response to start. Promise.all fires them simultaneously and resolves when both complete. Sequential awaits waste time waiting for the first request before starting the second.

Q12. How did you handle API errors in DevFinder? What is the difference between a 404 and a 403? Error Handling
  • 404 Not Found → User doesn't exist on GitHub. Message: "No user found with username X". This is an expected user error — the app recovers gracefully.
  • 403 Forbidden → GitHub API rate limit hit (60 unauthenticated requests/hour). Message: "Rate limit exceeded. Try again in a minute." This guides the user without confusing them.
  • Network error (catch block) → No internet / fetch itself throws. Message: "Network error. Check your connection."
  • Other non-OK → Generic "GitHub API error. Please try again."

Each error type gets a specific, human-readable message. A generic "Something went wrong" message is unhelpful and considered bad UX.

🎯 Interview Questions — Design Decisions

Q13. Why did you build everything without a UI library like Material UI or Tailwind? Architecture

Three reasons:

  • Demonstrates depth — Anyone can use a component library. Hand-crafting components proves you understand CSS flexbox, CSS variables, animation, and responsive design at a fundamental level.
  • Bundle size — MUI v5 adds ~100KB to the bundle. Zero UI library = zero overhead. This matters for Core Web Vitals.
  • Portfolio differentiator — Most portfolios look identical because they use the same UI kit. A custom design stands out in a recruiter's inbox.

In a professional project, I would absolutely use a design system (as I do at Newgen with MUI v5). The choice here is intentional — to show I can work at both levels.

Q14. How does your theme system work? Could it scale to support a user-defined colour scheme? CSS
/* The entire theme lives in CSS variables */
.app.dark  { --bg: #0f1117; --accent: #6366f1; }
.app.light { --bg: #ffffff; --accent: #4f46e5; }

/* Every component references variables, never hardcoded colours */
.card { background: var(--bg2); border: 1px solid var(--border); }

Yes — to support user-defined colours, you'd just read the user's preference and set document.documentElement.style.setProperty('--accent', userColour). Because every component uses var(--accent), the entire UI updates instantly. This is how VS Code's theme system works.

Q15. How is data structured in NovaDash? Why is all data in a single data.ts file? Architecture

All mock data arrays live in data.ts and all TypeScript interfaces in types.ts. This is the separation of concerns principle:

  • Components don't know about data shape — they receive typed props.
  • Pages receive pre-filtered data — they don't know about the search state.
  • In production, you'd replace data.ts with API calls and nothing else changes — because the types are already defined and the components are already typed.

This mirrors how real production codebases work — separate data layer, separate UI layer.

Q16. Your search clears when you switch pages. Is that intentional? Why? UX
// App.tsx — useEffect resets search on page navigation
useEffect(() => { setSearch(''); }, [page]);

Yes, intentional. This is standard UX behaviour — if you search for "Aarav" in Transactions and switch to Users, you don't want the Users page to also be filtered for "Aarav" because those are completely different data sets. Each page's search context is independent. Gmail, Notion, and Linear all reset filters when you switch views.

Q19. What is the .nojekyll file in your portfolio repo? Why is it needed? GitHub Pages

GitHub Pages runs Jekyll (a static site generator) by default before serving your files. Jekyll ignores directories and files starting with an underscore (_) — this would cause problems if your build output had _app/ or _next/ folders (like Next.js generates).

A .nojekyll empty file at the root tells GitHub Pages to skip the Jekyll build step entirely and serve files directly. For pure HTML sites, it ensures nothing gets accidentally processed or excluded.

Q20. What is vite-env.d.ts and why did it fix your build? Vite + TS
/// <reference types="vite/client" />

This triple-slash directive adds Vite's type declarations to the TypeScript project. Without it, TypeScript doesn't know that importing a .css file is valid (it's a Vite-specific transform), so it throws: "Cannot find module './App.css'".

Vite's type declarations include: CSS/SCSS module types, import.meta.env types, glob import types, and asset URL types. Every Vite + TypeScript project needs this file.

⚡ Quick Answer Cheatsheet

For rapid-fire technical questions, use these concise answers:

useState vs useRef

useState → re-renders on change. useRef → persists value without re-render. Use useRef for DOM refs or timers.

useMemo vs useCallback

useMemo caches a computed value. useCallback caches a function. Both accept dependency arrays.

Why Vite over CRA?

Vite uses native ESM + esbuild. Dev start: ~300ms vs 30s+. HMR <100ms. No webpack config overhead.

What is tree-shaking?

Bundler removes unused exports at build time. Vite/Rollup do this automatically. Reduces final bundle size.

CSS Variables vs Props

CSS vars cascade through DOM without JS — zero React overhead. Props require component re-renders. Vars are better for theming.

Why TypeScript strict?

Catches null access, implicit any, missing returns at compile time. Prevents entire classes of runtime bugs.

Controlled vs Uncontrolled

Controlled = form value in React state (recommended). Uncontrolled = value in DOM via useRef. Controlled is predictable and testable.

What is lifting state up?

Moving shared state to the closest common ancestor so siblings can communicate. Used in TaskFlow for modal state.

Memo vs useMemo

React.memo wraps a component — skips re-render if props unchanged. useMemo memoizes a value inside a component.

Why encodeURIComponent?

Encodes special chars in user input before using in URLs. Prevents URL injection, handles spaces, slashes, and non-ASCII chars safely.
